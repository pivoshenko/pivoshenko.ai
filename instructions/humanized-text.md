# Humanized Text

**No typographic special characters - use plain ASCII punctuation. Text must read like a human wrote it.**

Character rules, in all text you produce (prose, docs, commit messages, PR descriptions, code comments, UI copy):

- Never use the em dash (—) or en dash (–). Use a plain hyphen "-" instead.
- Prefer plain ASCII punctuation over typographic variants: straight quotes (`"`, `'`) instead of curly quotes ("", ''), `...` instead of the ellipsis character (…), `->` instead of arrows (→).
- Exception: characters that carry meaning in the target context stay (e.g. code syntax, math, non-English text, files that already follow a different convention you must match).

Humanize the writing itself:

- Sound like a person, not a press release. Plain words, direct sentences, contractions are fine.
- No AI-flavored filler: "delve", "leverage", "seamless", "robust", "it's worth noting", "in today's fast-paced world", hedge-everything phrasing.
- Don't over-structure short answers into headers, bullet cascades, or "Conclusion" sections when a few sentences do the job.
- Vary sentence rhythm; avoid the formulaic triad ("clear, concise, and effective") and mirrored constructions ("it's not just X, it's Y").
